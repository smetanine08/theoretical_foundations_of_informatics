## Задача и формат данных

Программа читает заказы, проверяет записи, выполняет поиск, фильтрацию,
сортировку, вычисляет статистику и сохраняет текстовый отчёт из девяти разделов.
Входной файл — UTF-8, без заголовка. Одна непустая строка — один заказ:

```text
номер;покупатель;категория;количество;цена;статус
```

Корректный пример:

```text
1001;Иванов Иван;Книги;2;750.50;выполнен
```

Некорректный пример:

```text
1013;Ошибка;Книги;0;10;новый
```

Количество равно нулю, поэтому запись пропускается. Сообщение содержит
физический номер строки файла и причину. Для одной ошибочной строки сохраняется
первая обнаруженная причина: количество ошибок равно количеству отклонённых строк.
Пустые строки не считаются ошибками. Номер занят только после принятия всей записи.

## Что хранится в программе

`orders` — список словарей. Список сохраняет порядок входных записей,
словарь даёт доступ к полям по понятным именам:

```python
{
    "id": 1001,
    "customer": "Иванов Иван",
    "category": "Книги",
    "quantity": 2,
    "price": 750.5,
    "status": "выполнен",
    "cost": 1501.0,
    "cost_category": "Средний",
}
```

`errors` — список сообщений. `seen_ids` — множество принятых номеров:
проверка `order_id in seen_ids` обнаруживает повтор.
Статистика по категориям — словарь вложенных словарей: ключом служит категория,
внутри лежат число заказов, число единиц товара, стоимость, выручка и среднее.
Глобально хранятся только настройки и константы. Основные данные создаются в main.

### Составной ключ без lambda

`sorted(orders, key=cost_sort_key)` вызывает cost_sort_key для каждого заказа.
Эта функция возвращает кортеж `(-стоимость, номер)`.
Python сравнивает первые элементы, и только при равенстве — вторые.
Минус меняет направление только для стоимости. Например, при стоимости 5000
заказ № 2 идёт раньше № 7. `reverse=True` для всей пары развернул бы и номера.

sorted создаёт новый список. Сами словари при этом остаются теми же объектами:
это не глубокая копия. Наши функции сортировки и фильтрации словари не меняют,
поэтому исходные данные сохраняются. `another = orders` вообще не создаёт новый список.

### Включение списка

```python
[order for order in orders if order["status"] == wanted]
```

означает: создать список, перебрать заказы и включить только подходящие.
Эквивалентная запись:

```python
result = []
for order in orders:
    if order["status"] == wanted:
        result.append(order)
```

### Границы и деньги

Малый: cost < 1000. Средний: 1000 <= cost < 5000. Крупный: cost >= 5000.
Условия проверяются сверху вниз. Проверяются 999.99, 1000, 4999.99 и 5000.
Стоимость равна quantity * price; округление происходит в выводе через `.2f`.
Например, 999.999 остаётся малым заказом, хотя на экране округляется до 1000.00.
Задание не запрещает цену с более чем двумя знаками после точки.

Используется обычный float, как в базовом Python. Он хранит числа приближённо:
3 * 0.1 может дать 0.30000000000000004. В проверке этого результата используется
малый допуск, а при выводе — два знака. Ничья покупателей сравнивается с допуском
1e-9 от масштаба суммы; это учебное допущение, а не точная финансовая арифметика.
Цена nan и бесконечность отклоняются; переполнение стоимости тоже обрабатывается.

### Выручка и лучшие покупатели

Общая стоимость включает все заказы. Выручка — только выполненные.
Для лучшего покупателя сначала складываются ВСЕ его выполненные заказы.
В тестовом файле Иванов: 1501 + 3499 = 5000; Соколова: 5000.
Поэтому показываются оба. Без выполненных заказов выручка 0,
лучшего покупателя нет. Для пустого списка среднее и самый дорогой заказ — None:
вывод объясняет отсутствие показателя, деления на ноль нет.
При равной максимальной стоимости самый дорогой заказ выбирается по меньшему номеру.

## Обработанные ошибки

Отсутствующий/недоступный файл; неверная кодировка; неверное количество полей;
пустое поле; нецелые номер и количество; неположительные числа; некорректная
цена, включая запятую вместо точки, nan и inf; переполнение стоимости;
повтор номера; неизвестный статус; неизвестный пункт меню; отсутствие результатов;
пустой поисковый запрос; пустой файл и отсутствие корректных записей;
отсутствие выполненных заказов; ошибка сохранения отчёта; окончание потока ввода.
В строке с несколькими нарушениями показывается первая причина.

Категории и имена хранятся с исходным регистром после strip.
Фильтрация и поиск не учитывают регистр. Статистика группирует по точному
написанию категории/имени: используйте единое написание одного покупателя и категории.
Такое объединение без учёта регистра для статистики в задании не предписано.

### Короткие ответы на типовые вопросы

- **return и print:** return передаёт результат вызывающему коду, print показывает текст.
- **Почему except недостаточно:** int("0") не вызывает ошибку, но количество 0 запрещено.
- **Фильтрация и сортировка:** первая отбирает элементы, вторая меняет их порядок.
- **Параметры и результат:** filter_by_status(orders, status) получает список и строку,
  возвращает новый список словарей; исходный список не меняет.
- **Зачем None:** это отсутствие значения, которое нельзя путать с допустимым нулём выручки.
- **Зачем if __name__ == "__main__":** main запускается при прямом запуске,
  при импорте можно отдельно вызвать функции и тесты.
- **Что делает assert:** проверяет условие; ложное условие вызывает AssertionError.
  Это проверка программиста, а не обработка ошибок входного файла.

Для небольшого изменения порога крупных заказов поменяйте LARGE_LIMIT;
понадобится обновить проверки границ и подписи «от 5000» в интерфейсе/отчёте.
Для добавления статуса измените STATUS_ORDER: множество допустимых статусов и
статистика строятся на его основе. Новый статус сам по себе не входит в выручку.
